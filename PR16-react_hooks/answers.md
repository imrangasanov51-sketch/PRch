# Ответы на вопросы для самоконтроля — ПР16

1. **useState vs useReducer**: useState — простое локальное состояние (число, строка, булево). useReducer — сложная логика обновления, несколько подполей, переходы состояний (как конечный автомат). Использовать useReducer, когда обновления связаны (форма, корзина, визард) или логика сложная; useState — для простых случаев.

2. **Массив зависимостей useEffect**: React сравнивает элементы массива с предыдущим рендером (Object.is). Если хотя бы один изменился — эффект перезапускается. Без массива — каждый рендер. Пустой [] — только монтирование. Важно: все используемые внутри значения должны быть в зависимостях (иначе stale closure).

3. **Stale closure**: функция внутри хука/эффекта захватывает устаревшее значение из старого рендера. Лечение: функциональные обновления `setCount(c => c + 1)` вместо `setCount(count + 1)`, добавление зависимостей, useRef для актуальных значений без перезапуска эффекта.

4. **useCallback и useMemo**: нужны, когда (а) функция передаётся в мемоизированный дочерний компонент (React.memo), (б) функция — зависимость другого хука, (в) вычисление очень дорогое и вход редко меняется. В остальном — преждевременная оптимизация: мемоизация сама стоит ресурсов. Профилируйте прежде чем применять.

5. **useRef vs useState**: useRef — изменение не вызывает рендер, .current мутируем. useState — каждое изменение рендерит. useRef незаменим: доступ к DOM-элементам, хранение id таймеров/интервалов, предыдущие значения, счётчики рендеров, актуальные значения внутри устаревших замыканий.

6. **Правила хуков**: вызывать только на верхнем уровне (не в циклах, условиях, вложенных функциях), только из React-функций (компоненты или кастомные хуки). Нарушение ломает порядок вызовов, React не сможет сопоставить состояние между рендерами. Плагин eslint-plugin-react-hooks ловит нарушения.

7. **Создание кастомного хука**: функция с префиксом use, внутри вызываем другие хуки, возвращаем { данные, методы }. Практики: один хук — одна задача, тестируемость, документирование параметров, обработка cleanup в эффектах, не нарушать правила хуков.

8. **useContext vs prop drilling**: контекст убирает необходимость передавать пропсы через каждый уровень — данные доступны на любой глубине. Плюсы: чистый код, независимость промежуточных компонентов. Минусы: избыточные рендеры при частом изменении, сложность тестирования. Для глобальных данных (тема, auth, locale) — отлично; для часто меняющегося состояния — лучше state manager или комбинация.

9. **Асинхронные операции в кастомных хуках**: через useEffect + fetch + флаги cancelled/isMounted для отмены; отдавать { data, loading, error }; cleanup обязателен; для отмены — AbortController, передавая signal в fetch; перезапуск по изменению параметров через массив зависимостей.

10. **Отладка хуков**: React DevTools (вкладка Components — видно хуки и их значения), console.log в эффектах, breakpoints в useEffect/useCallback, ESLint (react-hooks/rules-of-hooks, exhaustive-deps), инструменты профилирования рендеров, изоляция проблемного хука в минимальный пример.
