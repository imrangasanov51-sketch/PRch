# Ответы на вопросы для самоконтроля — ПР13

1. **Promise.then().catch() vs async/await с try/catch**: then/catch — цепочечный стиль, удобен для простых цепочек и комбинаторов (Promise.all и т.д.). async/await даёт синхронно-выглядящий код, удобен для последовательных операций и сложной логики с вложенными try/catch. Под капотом async/await — тот же механизм промисов. Используйте async/await в большинстве случаев, then/catch — в коротких цепочках.

2. **Promise.all**: принимает массив промисов и возвращает промис с массивом результатов в том же порядке. Выполняется параллельно, общее время = время самого медленного. Если хотя бы один промис реджектится — весь Promise.all сразу реджектится с той же ошибкой (остальные не отменяются, но их результаты теряются).

3. **Promise.all vs race vs allSettled**: all — ждёт все, падает при первой ошибке (загрузка всех данных страницы). race — возвращает первый завершившийся (таймауты, «кто быстрее»). allSettled — ждёт все, никогда не реджектится, возвращает статусы fulfilled/rejected для каждого (статистика, массовые операции, где важен результат каждого).

4. **Retry с экспоненциальной задержкой**: циклом повторять операцию в try/catch; при ошибке ждать `2^попытка * базовая_задержка` (например 500мс, 1с, 2с), пока не достигнут maxRetries, затем пробросить последнюю ошибку. Также добавляют jitter (случайность), чтобы не устроить «гром среди retry-штормов».

5. **Race condition**: ситуация, когда результат зависит от порядка/времени завершения асинхронных операций (например, два setState по одному счётчику, устаревший ответ API перезаписывает новый). Избежать: функциональные обновления состояния, AbortController для отмены устаревших запросов, флаги-версии, мьютексы/очереди для критических секций.

6. **Кэширование**: сохранение результата запроса в Map/объекте; при повторном запросе с тем же ключом возвращается сохранённое значение без сети. Стратегии: in-memory кэш, TTL (время жизни записи), LRU (выталкивание редкоиспользуемых), stale-while-revalidate (отдать кэш и обновить в фоне), кэширование в localStorage/SessionStorage, HTTP-кэш (Cache-Control, ETag).

7. **Оптимизация множественных асинхронных операций**: Promise.all для параллельности, дебаунс/троттлинг событий, кэширование, отмена устаревших запросов (AbortController), ленивая загрузка, пагинация, батчинг мелких запросов, профилирование через performance.now().

8. **Ошибки в цепочках промисов**: каждый .then должен либо возвращать значение, либо бросать ошибку; .catch в конце цепочки; в async/await — try/catch вокруг await. «Проглатывание» ошибок происходит, если catch не пробрасывает ошибку дальше или промис реджектится, а обработчика нет — всегда завершайте цепочку catch и/или используйте `unhandledrejection`.

9. **Преимущества async/await**: читаемость (нет «callback hell» и вложенных then), естественная обработка ошибок через try/catch, удобная отладка (обычные stack traces, точки остановки), совместимость с синхронными конструкциями (циклы, условия).

10. **Отладка асинхронного кода**: breakpoints в DevTools (даже внутри async), `debugger`, console.log с метками времени, вкладка Network для запросов, Performance/Profiler, Promise-таблицы в Chrome DevTools, логирование стека ошибок (error.stack), инструменты вроде React DevTools / Redux DevTools для UI.
