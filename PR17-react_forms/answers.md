# Ответы на вопросы для самоконтроля — ПР17

1. **Управляемые vs неуправляемые компоненты**: управляемые — значение поля хранится в state React, отображается из state, onChange обновляет state (React — «единственный источник правды»). Неуправляемые — значение хранится в DOM, читается через ref при необходимости.

2. **Когда использовать**: управляемые — по умолчанию, особенно когда нужна валидация, форматирование, условная логика, мгновенная реакция на ввод. Неуправляемые — файловые инпуты, интеграция со сторонними DOM-библиотеками, очень простые формы отправки, когда не нужна реакция на каждый ввод.

3. **Обработка событий в формах**: onChange (ввод), onSubmit (отправка), onBlur (потеря фокуса), onFocus. В React onChange срабатывает при каждом вводе символа (в отличие от нативного change). Форма отправляется по событию onSubmit на <form>.

4. **Один обработчик для нескольких полей**: использовать атрибут name на каждом поле и читать его из e.target: `const { name, value, type, checked } = e.target; setForm(prev => ({...prev, [name]: type === 'checkbox' ? checked : value}))`. Работает для input, select, textarea одинаково.

5. **Подходы к валидации**: (а) валидация при отправке (validate на submit), (б) валидация при потере фокуса (onBlur), (в) валидация при вводе (onChange с debounce), (г) схемная валидация через библиотеки (Yup + Formik, Zod + react-hook-form), (д) встроенная HTML5-валидация (required, pattern, minLength) + noValidate для кастомной.

6. **Предотвращение перезагрузки**: `e.preventDefault()` в обработчике onSubmit. Без этого форма отправляется по-умолчанию и страница перезагружается.

7. **Lifting state up в формах**: когда данные формы нужны родительскому компоненту (или нескольким компонентам), состояние поднимается к родителю, а полям передаются value + onChange через props. Родитель владеет состоянием, дочерние поля — «управляемые компоненты». Так работают Formik и подобные библиотеки.
